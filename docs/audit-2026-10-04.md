# Статус этапов дорожной карты по результатам аудита

Проверял: модели, миграции, роутеры backend/, документы `root-game/docs/`, фронтенд `root-game/src/`, тесты. Ниже — честная картина: что уже работает, что только заложено, чего нет вообще.

| Этап | Статус | Что сделано и что осталось |
|---|---|---|
| 1. Проектирование, документация, инвентаризация | **готов** | В `root-game/docs/` лежат 16 документов-контрактов (архитектура, правила игры, права админов, ledger, машины состояний миссий и др.), есть журналы цепочек миграций и gap-анализ. Контракты зафиксированы — можно сверять реализацию с ними. |
| 2. Фундамент: супер-админ, permissions, approvals, audit, system settings | **готов** | Модель админа с `is_super_admin`/`is_active`, таблица прав и выданных прав, заявки на подтверждение, неизменяемый аудит с функцией записи, системные настройки + их каталог и админ-роутеры, отдельные миграции и тесты на approvals/audit. Фундамент закрыт. |
| 3. CMS игровых заданий (сезоны, главы, миссии, награды, предметы, ключи, геозоны) | **в работе** | Есть модели сезонов, глав, сюжетных узлов, миссий, требований, наград, предметов, сегментов + админ-роутеры и валидация контракта, жизненный цикл draft→published→archived. Не сделано: ключи как отдельная сущность, пулы случайных наград, геозоны и AR-объекты, миграция demo-контента (demo-сид и публичный reset-API всё ещё живы). |
| 4. Инвентарь и ключи | **в работе** | Есть предметы, инвентарь игрока, выдача наград в движке, таблицы резервов и событий инвентаря, таблица fallback-наград. Не сделано: списание ключа и ROOT-взноса при взятии миссии, «ключ не возвращается», персональный магазин после первого провала — таблица лежит мёртвым грузом, логики вокруг неё нет. |
| 5. Карточка игрока, ручные операции, ограничения | **не начат** | Есть только таблица игроков с одним статусом «active». Нет админ-роутера с карточкой игрока, нет операций (начислить/списать ROOT, выдать ключ), нет системы ограничений (suspended, transfer_restricted и т.д.). Готов только инфраструктурный фундамент из этапа 2 (approval + аудит), на который это можно наращивать. |
| 6. Команды, приглашения, состав, чат | **не начат** | Постоянной сущности «команда», участников, приглашений и чата нет. Есть только временные «сессии команд» и «участники сессии» — это заглушки для командных миссий, а не система команд. |
| 7. Командные задания и совместная геоактивация | **в работе** | Заложен модельный фундамент: сессии команд с проверкой присутствия, попытки, запуски миссий, расчёты наград, политики runtime + контрактные документы и тесты (включая защиту «одиночный путь не тронет командный»). Не сделано: всё это не подключено к API и не может работать без сущности команды (этап 6). |
| 8. Геолокация, карта, AR-объекты, античит | **не начат** | Есть таблица гео-доказательств с полем `zone_id`, но справочника геозон нет — зона существует только как строка. Нет карты, AR-объектов, проверок скорости/устаревших координат. На фронте есть экран «Scanner», но это демо. |
| 9. Экономика ROOT и ledger | **в работе** | Кошельки и неизменяемый ledger проводок с уникальностью (защита от дублей) и резервами средств, настройки экономики (пороги переводов, дневные лимиты, порог ручной корректировки), документы по ledger. Не сделано: фоновая сверка «баланс = сумма проводок», реестр финансовых операций в админке, финансовые тесты. |
| 10. Переводы ROOT и комиссия в Stars | **не начат** | Есть только настройки-пороги в каталоге системных настроек (минимум выигрыша, минимум/максимум суммы, дневной лимит). Моделей переводов, платежей Stars и роутеров нет — заданы только будущие правила. |
| 11. Вывод в TON | **не начат** | Моделей TON-адресов, заявок на вывод, резервирования под вывод и интеграции с TON нет вообще. |
| 12. Магазин, Stars, операционная экономика | **не начат** | Есть документ-контракт fallback-магазина и пустая таблица fallback-наград, но логики магазина, предложений после провала и журнала Stars-платежей нет. |
| 13. Модерация, страны, логи, ошибки | **не начат** | Работает только аудит админских действий (из этапа 2) и middleware с идентификатором запроса. Нет политик по странам, логов действий игроков, системы сбора ошибок и модерации. |
| 14. Frontend и мобильный клиент | **в работе** | Telegram Mini App на React: 5 игровых экранов (архив, брифинг, инвентарь, сканер, терминал), API-клиенты и хуки, каркас админки. Не сделано: карта, команда и чат, баланс/переводы/вывод, магазин, все целевые разделы админки (Dashboard, игроки, экономика, модерация и т.д.). |
| 15. Тестирование, защита, запуск | **в работе** | Есть 9 файлов тестов (админ-заявки, аудит, валидация контентных контрактов, контракты гео-команд и runtime-политик, интеграция движка миссий), Docker, nginx, папка бэкапов. Не сделано: финансовые тесты, security-набор (rate limiting, инъекции, IDOR), мониторинг — их блокирует отсутствие функций этапов 5–13. |

**Общая картина в двух словах:** админский фундамент (этапы 1–2) и документирование закрыты; контентная CMS и командно-гео-ядро — в работе; экономика — половина пути (ledger есть, переводы/TON/магазин нет); команды, игроки, модерация и целевой фронтенд — ещё не начаты, хотя фундамент под них уже готов.
