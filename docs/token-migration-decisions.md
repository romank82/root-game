# Решения по переходу ROOT на mainnet

Зафиксировано 25.11.2026 по итогам разбора `token-migration-brief.md`.
Каждый пункт — решение владельца проекта. Менять только новым решением.

## 1. Экономическая модель: один актив

ROOT в игре и ROOT в блокчейне — **один и тот же актив**.

- Игрок может **вносить** ROOT из блокчейна и **выводить** обратно.
- Внесённый ROOT ничем не отличается от заработанного: им можно платить
  вход в миссии, покупать в магазине, переводить другим игрокам.
- Ограничения на перевод и вывод снимаются по достижении порога
  заработанных ROOT (уже реализовано через `minimum_earned_root_for_transfer`
  и правила вывода). После снятия ограничений источник ROOT не проверяется.
- Риск «купил дёшево → прошёл миссию → вывел» принят осознанно.
  Балансировка наград с оглядкой на внешнюю цену — задача экономики,
  а не техническая блокировка.

Следствие: **два актива не вводим**, моста и курса не будет.

## 2. Владение токеном

Владелец один. Мультисиг не используется.

- Одиночный кошелёк выплат, ключ у владельца в Tonkeeper.
- Основной объём эмиссии рекомендуется держать на холодном кошельке,
  на рабочий кошелёк выплат переводить порциями.
- Seed-фраза хранится офлайн в двух физических местах.
- Приватного ключа на сервере нет и не будет (текущая схема сохраняется).

## 3. Decimals

Оставляем **8 знаков** после запятой. `NANO_PER_ROOT = 100_000_000`
не меняется.

## 4. Тип минтера

**Стандартный `jetton-minter`** без админ-минта.

- Весь объём эмиссии (1 000 000 000 ROOT) создаётся один раз.
- Допечатать токены невозможно — ни владельцу, ни серверу.
- Это гарантия для игроков, что эмиссия не будет размыта.

## 5. Верификация токена

Требуется, но **не блокирует** технический запуск mainnet.

Нужно подготовить:
- сайт проекта (хотя бы лендинг);
- логотип токена (PNG/SVG);
- описание (название, тикер, назначение).

Подача метаданных на tonviewer/tonapi — отдельная задача, выполняется
параллельно с техническими работами.

## 6. Ликвидность

**На старте пула ликвидности не будет.**

- Токен деплоится в mainnet, вывод работает, продать ROOT пока негде.
- DEX-пул (STON.fi / DeDust) — отдельный этап позже, требует реальных TON
  и выбора стартовой цены.

## 7. Юридическая часть

Вопрос проработан с юристом. Отдельных технических требований
из этого не следует.

## 8. Технический долг: что закрываем ДО mainnet

| 2 | Deposit poller работает от `root` вместо `deployer` | **Закрыть до mainnet** |
| 3 | `deposit_service.process_incoming_transfer` не сверяет `to_address` | **Закрыть до mainnet** |
| 4 | Нет security headers в nginx | **Закрыть до mainnet** |
| 7 | TonCenter без API-ключа | **Получить ключ до mainnet** |
| 9 | Нет автоматизации бэкапов БД | **Сделать до mainnet** |

## 9. Технический долг: решения по поведению

- **Античит не отменяет награду** — оставляем как есть. При срабатывании
  флага блокируются только вывод и перевод до решения админа. Награда
  остаётся на балансе. Требует регулярного просмотра админки владельцем.
- **Автоподтверждение выплат** — реализуем. Сервер сам периодически сверяет
  блокчейн и подтверждает доставленные выплаты; кнопка «Сверить» остаётся
  как ручной fallback.

## 10. Мелочи (не блокируют mainnet)

- Убрать `environment` из ответа `/health`.
- Обновить уязвимые dev-зависимости фронтенда (`pnpm audit`: Vite,
  source-map-js). Влияют только на dev/CI.

## Открытые вопросы на будущее

- Пул ликвидности: когда, с каким объёмом, на какой DEX, стартовая цена.
- Верификация: кто делает сайт и логотип, сроки.
- Политика балансировки наград после появления рыночной цены ROOT.
